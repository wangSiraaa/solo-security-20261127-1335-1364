# 离线构建合作社 · 独立重建复核入口

回答的问题：**两份构建报告摘要一样，发行人真的拿到了两条独立见证吗？**

结论先行：摘要是**产物属性**，独立性是**路径属性**。相同摘要 + 两枚签章只能证明
"东西一样、各自签过"，不能证明"各自从源码走过一遍"。本工具把每次构建的**物件来源**
逐件登记，复核与签发都只看来源链，不看摘要脸色。

## 目录（小文本 + 两个本地目录）

```
coop/
├── coop-verify.sh      # 复核员本地入口：登记/构建/重建/签发/查验
├── run-demo.sh         # 一键复现全部主张与反例（六幕）
├── inputs/             # 全部输入只是几个文本文件
│   ├── source.txt      # 源码
│   ├── recipe.txt      # 配方（含展示件/功能件区分规则）
│   ├── gen-func.sh     # 本地输入生成器（确定性产出功能件）
│   ├── typeset-v1      # 原排版工具（封存旧环境，能重放原封面）
│   └── typeset-v2      # 干净环境排版工具（封面写入新日期）
├── room1/ room2/       # 两间构建室，各一个空档，环境装入后锁定
├── state/              # 登记库：依赖/构建记录/逐物件来源/证书/签章
└── dist/               # 出厂包、构建签章、构建公钥
```

## 核心规则（来自合作社章程）

- 功能文件 `func1.bin`/`func2.bin`：交付件，两间必须**逐字节相同**。
- 封面 `cover.txt`：展示件，允许清单内**仅印刷日期可不同**（归一化日期后须逐字相同）。
- 未声明的功能差异不得以封面日期为名豁免。
- 共享中间件允许，但必须**如实声明**；甲订单接受，乙订单拒绝。
- 每间构建室本班只有一个空档；环境装入后不可更换。
- 临开工送到的独立材料必须**单独登记**，未登记材料进不了构建工作区。

## 子命令

```
init                                            初始化状态库、签章密钥、共享预制件
register-source                                 登记源码/配方/输入生成器
register-dependency <room> <name> <path> <origin> [transient] [retain]
register-late <room> <fragment>                 单独登记迟到独立材料
load-env <room> sealed-old|clean                装入并锁定环境（本班不可换）
build <room> [--use-shared-prebuilt]            实际构建，逐物件登记来源
rebuild-check <room>                            复核员强制从源码本地重建比对
set-policy <room> jia|yi [cover-strict]         登记订单方与封面差异政策
issue-cert <room> functional-reproduction|verbatim-package
verify <room> <ctype>                           查签章、实物摘要、来源链现状
tamper-origin / restore-origin                  演示来源篡改与恢复
retract-tool / restore-tool                     模拟临时排版工具收回/放回
list                                            打印全部登记
```

两类证明：

| 证明 | 功能件 | 封面 | 来源链要求 |
|---|---|---|---|
| `functional-reproduction`（独立功能复现） | 两间逐字节相同 | 允许日期展示差异 | 乙：两件都须 source-build |
| `verbatim-package`（整包逐字复刻） | 两间逐字节相同 | 也须逐字节相同 | 甲：允许已声明的 shared-prebuilt |

## 六幕演示与题面映射（`bash run-demo.sh`）

1. **干净双路径**：room1 封存旧环境、room2 干净环境，各自源建；功能件摘要相同，
   封面日期相差一天 → 乙领到独立功能复现证明。
2. **只改来源不改摘要**：把 room2 的 func1 来源登记为 `copied-from-other-room`，
   摘要与签章纹丝不动，`verify` 立即判来源链失效——相同摘要不能证明独立。
3. **乙收紧封面政策**：`set-policy room2 yi cover-strict` 后，同样的日期差异使该证明
   不可签发；改回允许展示差异后恢复。
4. **封存旧环境 + 共用预制件**：功能件出自两间共用预制件、封面重放原日期。
   甲可领整包逐字复刻证明（共享中间件已声明）；同一包挂乙订单则被拒。
   且强制源码重建依然逐字节通过——**重建比对本身分不出预制件，只有来源登记能分**。
5. **变化一·临时排版工具**：未留存副本即被收回时，封面无法重建，含封面的承诺失效
   （功能件复核不受影响）；登记 `retain` 并留存副本后承诺可兑现。
6. **变化二·迟到独立材料**：未登记材料被构建门禁拦下；两间各自单独登记同一份材料
   后独立性与一致性同时成立；只有一间并入时功能件出现差异，证明拒签，不许算在
   封面日期头上。
